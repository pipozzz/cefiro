# v0.24.0-beta

## Summary

A discovery and growth release. The goal is to turn a private library into
**public recipes that people can actually find** — through richer discovery,
semantic themes, cuisine landing pages and better search metadata — while making
sure only content you have the right to share ever goes out. Alongside that:
web push notifications, branded and localized emails, first-party analytics, and
Terms of Service / Privacy pages.

## Features

### Discovery & SEO

- **Cuisine hub pages.** Every cuisine that has public recipes gets a crawlable
  landing page at `/discover/cuisine/<cuisine>`, plus an index at
  `/discover/cuisine`. They are server-rendered and added to the sitemap, so
  search engines and readers get real pages that grow automatically as more
  recipes are published.
- **Semantic themes.** Public recipes are embedded (pgvector) and clustered into
  named themes on the Discover page; each theme tile runs a vector-similarity
  search, so "what goes together" is learned from the catalogue rather than from
  tags. Small catalogues still get sensible themes.
- **Richer recipe metadata.** Recipe pages emit fuller `Recipe` JSON-LD —
  cuisine, and step-by-step `HowToStep` entries with names, anchors and images —
  so results can show rich snippets.
- **Discovery polish.** Cleaner theme strip, better empty / cold-start states,
  and clearer logged-out landing copy.

[Discovery configuration](../configuration/discovery.md).

### Publishing & copyright safety

Growing public content must not publish work you don't own. Three layers now
guard that:

- **Publish-time warning.** Sharing a single imported recipe warns first — its
  photos and prose may belong to the original source.
- **Bulk-publish guardrail.** The bulk sharing manager will **not** make imported
  recipes public. A "publish everything" sweep silently skips them (and reports
  how many), because a bulk action offers no per-recipe judgement. Your own
  authored recipes publish normally.
- **Unpublish imported.** A one-click cleanup in the sharing manager pulls every
  imported recipe that is currently public or link-only back to private and out
  of discovery — for tidying up content shared before the guardrails existed.

Imported recipes are badged in the sharing manager so you can always see which is
which.

### Web push notifications

- Opt-in **web push** for the social events that matter: new follower, like,
  comment, save, and a reported comment. Toggle it on per device; text is
  rendered in the instance's default language.

[Notifications configuration](../configuration/notifications.md).

### Email

- **Branded, localized transactional emails.** Household invites, instance
  invites and the admin test email now carry the app logo, brand styling and a
  footer, and render in the instance's default language (Slovak and English
  ship, with English as the fallback).
- **Admin test-email button** to verify SMTP delivery — and the branding — at a
  glance.

[Email configuration](../configuration/email.md).

### Analytics

- **First-party Plausible.** Analytics is served through a first-party proxy that
  works with runtime environment configuration, so tracking is not blocked by ad
  blockers and needs no third-party script. The old analytics path was removed.

[Analytics configuration](../configuration/analytics.md).

### Legal

- **Terms of Service** and **Privacy Policy** pages, with a consent checkbox
  recorded at signup.

## Fixes and Improvements

- The brand logo now shows on mobile in the app shell.
- Theme clustering works on a small catalogue and reports how many recipes back
  each theme.
- Plausible now initializes reliably (loaded via `next/script`).

## Upgrade notes

This release adds several optional configuration areas. See the linked
configuration pages above for details; new environment variables are documented
in `.env.example`.

- **Email:** `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`,
  `SMTP_PASSWORD`, `EMAIL_FROM`. Port `465` needs `SMTP_SECURE=true`; `587` needs
  `SMTP_SECURE=false`. Set **`AUTH_URL` to your public HTTPS domain** so the
  email logo resolves for recipients.
- **Web push:** `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
- **Semantic discovery:** `VOYAGE_API_KEY` for embeddings.
- **Analytics:** `PLAUSIBLE_DOMAIN`, `PLAUSIBLE_SRC`.
- **Default language for emails and push:** `DEFAULT_LOCALE` (or the admin
  locale configuration).
